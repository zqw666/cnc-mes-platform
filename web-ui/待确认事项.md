## 2. 西门子机床"启动加工"的执行方式（已确认：PLC 发送命令）

**结论**：采用 PLC 发送启动加工命令，已在代码中实现（先按模拟地址跑通，现场地址待填）。

**现状（改造前）**：
- `load_machine` 放完工件后调用 `MacStartProcessSafe(macnum)`（见 `HandleUploadProgram`）
- 但 `Siemence.MacStartProcess()`（`mac/MacCommunicate/MacCommunicate/Siemence.cs:82`）方法是**空的**，恒返回 `false`
- 结果：西门子机床上件后工件状态停留在"待加工"，不会进入"加工中"

**已实现方案**：一次流程仍只上 1 件（放到第一个空工位）；**放满 4 件后**才执行 `HandleUploadProgram`（合并上传 + PLC 启动），启动成功后该机床所有有件工位置"加工中"。西门子机床（`type=siemense`）且配置了启动任务号时，`HandleUploadProgram` 改走 PLC 通道（复用机器人任务模式 `ExecuteTask`）：

```
① Plc.WriteDM(任务号DM, 启动任务号)
② Plc.WriteWR(开始信号, 1)
③ 轮询等待完成信号 == 1
```

对应 `config.json`（运行时 `...net472/config.json`）：

```json
"plc": {
  "signals": {
    "robot":  { "taskNumber": "D100", "taskStart": "104.00", "taskDone": "205.00" },
    "machine": { "startTaskNo": "300" }
  }
}
```

- 任务号 300 为**模拟占位值**，可被 `plc.signals.machine.startTaskNo` 覆盖
- DM/开始/完成信号地址沿用机器人信号（D100/104.00/205.00），与模拟器默认一致
- 未配置 `machine.startTaskNo` 时回退 `MacStartProcessSafe`（西门子仍会失败，需保持配置）

**放满 4 件才启动（2026-08-05 新增需求）**：
- 前 3 件只写入工位表（`workpiece_status=0` 待加工），**不启动加工**，流程正常结束等待下次上机
- 第 4 件放满后：上传合并程序 → PLC 发送启动命令 → 该机床 4 个有件工位全部置 `workpiece_status=1`（加工中）
- 合并程序格式仍待现场提供样例（见第 4 项表格）

**仍待现场确认**：
- 现场 PLC 里机床启动加工实际的 **DM 任务号地址**？
- **开始信号 WR** 地址？
- **完成信号 WR** 地址？
- 启动任务号的真实值（当前占位 300）？
