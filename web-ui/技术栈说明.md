> 对象：MES 产线管控系统（MachineMonitor）  
> 整理日期：2026-11-04  
> 用途：接手、排期、技术选型时的唯一参照。所有版本号均从工程文件读取，不是估计值。

## 0. 一句话

一套跑在工控机上的 **.NET Framework 4.7.2 单体服务 + 静态多页前端 + 14 个独立子程序 exe**，零前端构建链，零外部运行时依赖，拷到机器上就能跑。

### 2.6 环节定义编辑（元数据闭环）

`node-types.json` 是环节的单一真源。原来只能手改 JSON 再重编译，现在有页面：`lowcode/node-types-editor.html`（设计器左侧「环节库 → 定义」进入）。

| 项     | 说明                                                                                                                       |
| ----- | ------------------------------------------------------------------------------------------------------------------------ |
| 可改    | 分组增删改、环节增删改（key/显示名/分组/默认启用）、专属字段增删改、通用字段改                                                                               |
| 字段属性  | name、type、label、unit、default、min、max、hint；`enum` 额外有 options（每行 `value=显示名`）                                             |
| 类型限制  | 只给 5 种：`text` / `number` / `switch` / `enum` / `path` —— 与 `lowcode/renderer.js` 注册表严格一致，避免配出渲染不出来的字段                            |
| 保存前校验 | 标识合法性与唯一性、字段名唯一、**字段名不能与通用字段重名**（否则属性面板出现两个同名控件）、`enum` 必须有选项且默认值在选项内                                                    |
| 双写    | 保存时写 `ExeDir/node-types.json`（运行时生效）；若往上能找到 `MachineMonitor.csproj`，**同时写源码副本** —— 否则下次 `dotnet build` 会用旧源文件把界面上的改动覆盖回去 |
| 高级入口  | 「JSON」按钮可直接编辑原文，应用前做 `JSON.parse` 校验                                                                                     |

生效路径：改完保存 → 刷新设计器 → 环节库与属性面板自动跟着变。**不需要重编译**。

### 2.7 系统参数（config.json 编辑）

| 项    | 说明                                                                           |
| ---- | ---------------------------------------------------------------------------- |
| 页面   | `lowcode/system-config.html`（设计器顶栏「参数」进入）                                            |
| 结构定义 | `lowcode/config-schema.js`（挂到 `window.CONFIG_SCHEMA`）                                |
| 分页   | PLC 连接 / PLC 信号映射 / 机床 / 料架 / 夹爪 / 线体 / 扫码器 / 上游生产系统 / 本机数据库 / NC 程序服务器 / 其他 |
| 写入接口 | `POST /api/config/raw-save` —— **原样写入，不做白名单重拼**                              |
| 校验   | 必填、IP 格式、PLC 地址格式（`505.09` / `D200` / `801`）、**同一地址被多处占用**                   |
| 安全   | 拒绝不含 `plc` 或 `database` 的配置（防写空）；写盘前留 `.bak`                                 |

**为什么不用 .json 存 schema**：`HomeController` 只服务 js/css/html/图片。放开 `.json` 会让 `/config.json` 变成可下载的静态文件 —— 里面有数据库明文密码。所以 schema 用 `.js` 承载。

**为什么不用老的 `SaveConfig`**：它是白名单重拼，会丢字段 ——

| 丢失项                                                     | 后果                     |
| ------------------------------------------------------- | ---------------------- |
| `machines[].aluminumGrabTaskNo` / `aluminumPlaceTaskNo` | 铝板电极上下机用错任务号           |
| 顶层 `eman`                                               | 上游生产库地址丢失，扫码流程失效       |
| 顶层 `nc_server` / `serverIp` / `log`                     | NC 共享路径、服务 IP、日志保留天数丢失 |

新接口规避了这个问题，同时把铝板两个字段补进了老接口的白名单（老页面保存不再丢）。

**同步 subs 默认不勾选**：本项目两份 config 实际是**两条不同产线**（主配置 = 电极线 `quick-electrode` + 8×10 料架 + 3 台机床；`subs/config.json` = 钢件线 `fixed-single` + 6×10 料架 + 2 台机床），覆盖前必须人工确认。

**运行模型**：每个 exe 有自己的 `Main()`，跑完退出，**进程间零内存共享**。主程序用 `ProcessStartInfo` 启动，`WaitForExit(timeout)` 等待，超时或取消时 `Kill()`。


**现状问题**：`Main()` 返回 `void`，拿不到真实执行结果。主程序只能判断"进程有没有退出"，判断不了"这一步成功没有"。

## 5. 明确不做的事

1. **不给前端加构建链。** 一旦上 webpack/vite，93 KB 的 `script.js` 全要重写，那是一个独立项目。
2. **不把 schema 存进 MySQL。** `flow.json` 是文件，能看 diff、能手工改、能进 Git，这是优点不是缺点。`node-types.json` 同理。
3. **不引入 Node 中间层进主链路。** 早期架构里有过 `server.js`（express 4.18.2 + mysql2 3.6.5 + ws，:3000），但当前主线副本**没有这个文件**，主链路只走 C# 的 8888。工控机多装一个运行时是净负担。
4. **不为参数默认值上代码编辑器。**
5. **不重构前端、不补单元测试、不升框架版本。** 投入产出比太低，一个人扛不住风险。

### 7.1 夹爪类型兜底加固（2026-11-04 已修复）

**故障现象**：电极线（`quick-electrode`）上，夹爪类型读不到时会静默退回 `fixed-single`（钢件夹爪），  
子程序用钢件夹爪去抓电极，日志里没有任何异常，事后无法定位。

**三层兜底全部指向钢件夹爪**，任一层出问题都会静默出错：
