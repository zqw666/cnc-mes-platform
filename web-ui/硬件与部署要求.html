适用于 MachineMonitor 工序编排系统（Web 前端 + 主控后端 + 14 个子程序）在新建产线或更换工控机时的适配与验收

0概要与最小配置

采购或改造工控机时，先按这张表对，其余细节看后续章节。

类别最小可行推荐说明
操作系统 Windows 10 Windows 10 专业版 Win7 SP1 也能跑，但需另装 .NET 4.7.2
运行时 .NET Framework 4.7.2 4.7.2 或 4.8 主程序与全部子程序的编译目标，低于此版本无法启动
CPU 双核 i3 级别及以上 主程序仅 9 个线程，瓶颈不在 CPU
内存 4 GB 8 GB 实测主程序 39.9 MB，子程序顺序执行，峰值约 150 MB
硬盘 128 GB SSD 256 GB SSD 程序本体仅 19 MB，空间主要留给数据库与 NC 临时文件
网口 2 个独立千兆网口（硬性要求） 上位网与设备网必须物理隔离，不能用单网卡 VLAN 替代
PLC 欧姆龙 NX / NJ / CP 系列（FINS 协议） 换品牌需重写通讯层，见附录一
数据库 SQL Server 2012+ SQL Server 2016+ 或 MySQL 8.x 本机部署，当前连接 127.0.0.1
两处最容易漏、漏了会出事故的 ① 子程序配置兜底：subs\config.json 必须随程序一起部署，且内容与主配置一致。缺了或错了，子程序会报错退出（2026-11-04 起不再静默用默认夹爪），日志里会写明「配置缺少 line.gripperType」及配置来源。
② 流程配置目录：flows\ 必须一起带走，否则主程序按内置默认顺序生成 11 步流程，与实际工艺不符。

A软件环境

这几项是硬约束，装错版本程序直接起不来。

项目要求等级依据 / 说明
操作系统 Windows 10（Win7 SP1 亦可） 硬约束 全部项目基于 .NET Framework，只能在 Windows 上运行
.NET Framework 4.7.2 及以上 硬约束 主程序与 14 个子程序的 TargetFrameworkVersion 均为 v4.7.2
数据库 SQL Server 或 MySQL 8.x 硬约束 当前 database.type = sqlserver；代码同时兼容 MySQL（需 MySql.Data 8.3.0，已在 lib 目录）
Web 服务器 不需要 IIS 不需要 后端用 HttpListener 自建，前端为静态文件，无构建链
前端运行时 浏览器（Chrome 87+ 或 Edge） 推荐 页面用到 flex gap、CSS grid、inset 等特性，过旧内核会错版
其他依赖 Node / Python / Java 均不需要 不需要 前端零构建，第三方库（Vue2 / Element / amis / SortableJS）直接放 lib 目录

B工控机硬件

带实测数据的规格要求，不是经验估算。

部件最低推荐等级依据
CPU 双核 2.0 GHz 四核 i3 级别 推荐 主程序仅 9 个线程；开销集中在数据库查询与 OPC UA 通信，不在计算
内存 4 GB 8 GB 推荐 实测：主程序工作集 39.9 MB；子程序单进程约 100 MB；同一时刻只跑 1 个子程序，峰值约 150 MB
硬盘 128 GB 256 GB SSD 推荐 程序总体积 实测 19 MB（其中 subs 子程序目录 6.4 MB）；空间主要留给数据库增长
网络接口 2 个独立千兆网口 硬约束 上位网与设备网物理隔离，详见 C 章节
串口 按需 1 × RS232 按需 仅当扫码器使用 RFID 串口（scanner.rfidCom = COM3）时需要；当前配置走网口 RCD，可不配
显示 能开浏览器 工控机自带触摸屏 硬约束 Web 服务只监听本机回环地址，前端只能在工控机本机访问，见 C5
电源 — 宽压工业电源 + UPS 推荐 程序无断电保护；flow.json 类配置有临时文件替换机制，数据库未提交的事务会丢
硬盘容量的真实算法 程序只占 19 MB，但 workflow_log 表只写不读、没有清理逻辑，每次工作流运行会为每一步写若干行。
估算方式：（每轮步骤数 × 每步日志行数 × 每天轮次 × 保留天数）× 单行字节数。按 11 步、每步 3 行、每天 200 轮计算，一年约几十万行 —— 128 GB 够用，但建议定期归档或加清理策略。

C网络要求

这是整套系统最容易出问题的一环，四个网段必须理清。

编号用途地址 / 端口等级说明
C1 上位网 192.168.125.x
本机 .201		 硬约束 对应 config.serverIp。办公网访问、上位系统对接走这张网卡
C2 设备网 192.168.101.x
PLC .10／机床 .51-.53／扫码器 .71		 硬约束 与上位网物理隔离，必须独立网卡。设备全部在此网段
C3 上游生产系统（EMAN） 172.16.129.243:1433 硬约束 扫码子程序查 verifyID 与工件名。连不上则扫码流程直接失败
C4 NC 程序共享 \\192.168.1.100\share 按需 第三个私网段，与前两个都不同。现场若无此服务器，NC 上传下载功能不可用
C5 Web 服务端口 8888，仅 localhost / 127.0.0.1 硬约束 代码固定只注册回环前缀，远程浏览器无法访问
C6 设备端口 PLC 9600（FINS/UDP）
机床 4840（OPC UA）
扫码器 5000		 硬约束 端口需在设备侧防火墙放通；PLC 当前走 UDP，不保证送达
C7 IP 分配 固定 IP，禁用 DHCP 硬约束 子程序写死 http://localhost:8888 回调主程序；IP 变动会导致设备通讯全部失效
C5 的实际后果 如果领导或工艺人员希望在办公室的电脑上打开编排页面，现在做不到。
改造方式二选一：① 给 HttpListener 增加 http://+:8888/ 前缀，需管理员权限并执行 netsh http add urlacl；② 前置 nginx 做反向代理。
两种都属于代码/部署改造，不是配置项。
C4 需要现场确认 nc_server.root_path 指向 192.168.1.100，与前两个业务网段都不在同一个网。要么现场确实存在这台文件服务器（需要第三条路由），要么这个字段是从别的项目沿用的、实际未启用。

或 RFID 串口		 推荐 两种都有实现，改 scanner.type（rcd / rfid）即可
夹爪 快换电极夹爪
line.gripperType = quick-electrode		 硬约束 类型必须与 grippers[] 里的 type 一致，否则用错夹爪动作

铝板料架 8×10		 可配 racks[] 支持自由增删，层数与每层位数可配

若日志出现「已回退到 …（可能已过期）」，说明后端没响应、配置来自本地文件，此时应核对产线是否正确。

E部署必须随行的文件

换新机器时漏掉任何一项，都会导致功能缺失或行为异常。

编号文件 / 目录等级缺失后果
E1 根目录 config.json 必备 PLC IP、机床列表、料架、夹爪全部为空，系统无法通讯
E2 subs\config.json 必备 子程序兜底配置。缺失则子程序无法判定夹爪类型，拒绝启动并报错退出
E3 flows\ 目录 必备 流程编排唯一真源。缺失则按内置默认顺序生成 11 步，与实际工艺不符
E4 subs\ 下 14 个 exe
及各自 .exe.config		 必备 子程序本体，缺失则该步骤报「程序不存在」并中止流程
E5 通讯依赖 DLL
PLC.dll / Opc.Ua.Client.dll / MacCommunicate.dll / Rcd.dll 等		 必备 编译期引用，缺失则子程序启动即崩溃
E6 node-types.json 重要 环节元数据。缺失则环节库为空，编排页面无法使用
E7 lowcode\ 目录
4 个页面 + renderer.js + config-schema.js		 重要 低代码页面本体，缺失则设计器打不开或属性面板空白。_proto\ 是弃用原型，构建时已排除、不需要拷
E8 开机自启配置 重要 程序自身不注册自启，需通过任务计划或启动项配置
E9 logs\ 与 nc_temp\ 目录 自动 首次启动会自动创建，无需手工准备
不需要带的东西 bin\ 下的 *.pdb（调试符号）、obj\、*.bak、源码目录均可排除，不影响运行。

F上线前核对清单

按顺序执行，前一项不通过不要进入下一项。

  1. 网络连通：ping 192.168.101.10（PLC）通；能访问 172.16.129.243（EMAN）。
  2. 端口连通：telnet 192.168.101.10 9600（PLC）；机床 4840；扫码器 5000。
  3. 数据库就绪：能连上业务库，且 macmessage 表有数据（机床号从该表动态查询，表空则「无待机机床」直接退出上机流程）。
  4. 两份配置一致：根目录 config.json 与 subs\config.json 的 line.gripperType、racks、machines 必须一致。可用「系统参数」页面核对。
    核对方法：启动任一子程序，日志第二行应出现 夹爪类型: quick-electrode（配置来源: 后端 API …）。若来源显示「本地回退文件」或「向上查找到」，说明后端没响应，需先解决再投料。
  5. 流程正确：编排页面的步骤顺序、启用项与工艺一致；timeoutSec 按各工序实际节拍设置，不要全部沿用 300 秒默认值。
  6. 仿真试跑：保持 simulate = true 跑完整一轮，确认流程能走通、失败策略符合预期。
  7. 单步真跑：关闭仿真，只启用 1 个步骤，超时设 30 秒，验证子程序能正常启动与退出（日志出现「已启动 (PID xxx)，超时 30s」）。
  8. 逐步放开：确认单步无误后，再按顺序启用其余步骤。
第 6、7 步不要跳过 直接关仿真跑全套流程，一旦某步出现设备动作异常，现场很难判断是哪一步引起的。先单步、再全流程，是唯一安全的验证路径。

一附录：更换 PLC 品牌的评估

当前通讯层只支持欧姆龙 FINS 协议，换品牌不是改配置能解决的。

现状

位置事实
PLC\PLC\PLC\plc.cs类 plc 内部固定实例化 mcOMRON.OmronPLC(TransportType.udp)

配置项plc 下只有 ip / port / signals，没有协议类型字段

按更换程度分三档

情形工作量说明
仍为欧姆龙（NX / NJ / CP） 0 代码改动 只改 config.plc.ip、port、signals。半天（含现场实测地址）
欧姆龙但改用 FINS/TCP 1 小时 TransportType.udp 改为 tcp，或加构造参数。建议优先走 TCP，UDP 不保证送达
换品牌（西门子 / 三菱 / 汇川 / 台达等） 5–8 天 需新写通讯实现 + 增加接口抽象层 + 改 14 个子程序的调用点

二附录：已知限制与风险

部署前应知悉，部分需要额外改造才能规避。

编号限制影响现状与建议
R1 Web 只监听回环地址 高 远程无法访问页面。需加 http://+:8888/ 前缀（含 URL ACL）或前置反向代理
R2 子程序硬编码 http://localhost:8888 高 子程序必须与主程序同机部署，无法拆分到不同服务器
R3 配置读取失败时静默用默认值 已修复 2026-11-04 已加固：line.gripperType 读不到时子程序报错退出，不再退回钢件夹爪；配置来源（后端 API / 本地回退文件）每次启动都打进日志，回退时强制 WARN 提示「可能已过期或属于其它产线」
R3.1 子程序 exe 旁残留 config.json 低 unload_machine\bin\Debug\config.json（2026-09-11 调试遗留）位于向上查找路径上，后端不可达时会被命中。现已打 WARN 告警，建议部署前删除该文件
R4 workflow_log 只写不读、无清理 中 长期运行持续增长，且写库异常被 catch {} 静默吞掉。建议加保留天数清理策略
R5 子程序 Main() 返回 void 中 部分子程序拿不到执行结果，只能靠退出码约定判断。已在主控侧按退出码兜底
R6 PLC 走 UDP 中 不保证送达，偶发读不到信号。若设备支持，建议改 TCP
R7 零自动化测试、5 份项目副本 中 改动无回归保障；副本间易改错版本。建议先做 Git 版本管理
