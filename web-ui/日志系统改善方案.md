# 日志系统改善方案

> 整理时间：2026-08-06
> 涉及文件：`web-ui/backend/Program.cs`、各子流程 `Program.cs`、`transfer.cs`
> 涉及表：`process_log`、`runlog`、`processlog`

---

## 1. 现状审计

### 1.1 日志表结构（3 张表 + 1 张流程步骤表）

| 表名 | 用途 | 实际使用情况 |
|------|------|-------------|
| `process_log` | 流程日志 | ✅ 子程序通过 `/api/sub/log` 写入，`/api/logs` 查询 |
| `runlog` | 运行日志 | ❌ 只在建表时创建，没有任何代码写入 |
| `processlog` | 加工状态跟踪 | ❌ 名字误导——实际存的是 `process_status`、`workpiece_name`，不是日志，用于 Dashboard 统计 |
| `workflow_step` | 流程步骤状态 | ✅ 记录各步骤的状态（idle/running/error） |

### 1.2 日志写入路径（混乱点）

```
子程序 Program.cs（5 份）
  ├─ Console.WriteLine(msg)          ← 控制台输出（78 处，11 个文件）
  └─ POST /api/sub/log               ← HTTP 到后端
       └─ backend ReceiveSubLog()
            └─ WriteStepLog()
                 ├─ INSERT INTO process_log    ← 写数据库
                 └─ AllLogs.Enqueue()          ← 内存队列（供前端实时显示）
```

### 1.3 关键问题

#### 问题 1：代码重复——5 份一模一样的 Log 函数

每个子程序有一份独立 `Log()` 函数（`load_machine/Program.cs`、`transfer.cs`、`change_machine/Program.cs`、`prepare_material/Program.cs`、`unload_machine/Program.cs`），内容完全相同：

```csharp
static void Log(string level, string content) {
    string msg = "[" + level + "] " + content;
    Console.WriteLine(msg);
    // POST /api/sub/log ...
}
```

改一个地方要改 5 个文件。

#### 问题 2：Console.WriteLine 散落 78 处

直接输出到控制台，不经过日志系统。子程序退出后这些输出就丢了，无法追溯。

#### 问题 3：3 张表功能重叠

- `runlog` 无人写入，成为死表
- `processlog` 表名误导，实际是加工状态统计（`process_status`），不是日志
- 写日志的人很难判断该用哪张表

#### 问题 4：无日志级别控制

所有级别（INFO/ERROR/WARN）都写入同一张表，无法按级别过滤或抑制低级别日志。

#### 问题 5：无日志清理策略

`process_log` 表无数据归档或清理机制，生产环境运行时间长后会无限增长。

#### 问题 6：operator 字段永远为空

`process_log.operator` 在 `WriteStepLog` 中传空字符串，没有记录操作人。

#### 问题 7：backend 自身没有 Log 函数

后端 `backend/Program.cs` 直接调用 `WriteStepLog` 或 `Console.WriteLine`，没有统一的 Log 入口。

## 2. 改善方案

### 2.1 总体架构

```
┌─────────────────────────────────────────────────────────────┐
│                    统一日志库 LogHelper                      │
│  (CommonOperateDll/LogHelper.cs, .NET Framework 类库)       │
│                                                             │
│  LogHelper.Info(step, msg)     ← 自动记录级别、时间、操作人  │
│  LogHelper.Warn(step, msg)                                  │
│  LogHelper.Error(step, msg)                                 │
│  LogHelper.Debug(step, msg)    ← 可配置是否输出              │
│                                                             │
│  LogHelper.LogToConsole()      ← 控制台输出                  │
│  LogHelper.LogToDB()           ← 写入 process_log            │
│  LogHelper.LogToFile()         ← 写入本地文件（新增）        │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 表结构优化

#### 保留 `process_log`，废弃 `runlog`，`processlog` 改名

**`process_log`（主日志表，优化后）**

```sql
CREATE TABLE process_log (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  step_name   VARCHAR(100) NOT NULL,       -- 流程名（load_machine / change_machine…）
  log_level   VARCHAR(20) NOT NULL,        -- INFO / WARN / ERROR / DEBUG
  log_content TEXT NOT NULL,               -- 日志内容
  operator    VARCHAR(100) DEFAULT '',     -- 操作人（可从配置/登录态获取）
  machine_id  INT DEFAULT 0,              -- 关联机床 ID（新增）
  created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
  INDEX idx_level (log_level),
  INDEX idx_step (step_name),
  INDEX idx_time (created_at)
);
```

**`runlog`** → 标记为废弃，不再建表，数据归入 `process_log`。

**`processlog`** → 改名为 `process_status`（明确为加工状态表），与日志分离。

### 2.3 配置项（config.json 新增）

```json
{
  "logging": {
    "level": "INFO",                   // 日志级别：DEBUG/INFO/WARN/ERROR
    "console": true,                   // 是否输出到控制台
    "database": true,                  // 是否写入数据库
    "file": {                          // 文件日志（新增，可选）
      "enabled": false,
      "path": "D:\\erp\\logs",
      "maxDays": 30,
      "maxSizeMB": 100
    },
    "operator": "system"               // 默认操作人
  }
}
```

### 2.4 集中式 LogHelper 类设计

**位置**：`CommonOperateDll/LogHelper.cs`（所有子程序已引用 CommonOperateDll）

```csharp
public static class LogHelper
{
    // 配置
    public static string Level = "INFO";
    public static bool ConsoleEnabled = true;
    public static bool DatabaseEnabled = true;
    public static string DefaultOperator = "system";

    // 对外接口
    public static void Info(string step, string msg)    => Write("INFO", step, msg);
    public static void Warn(string step, string msg)    => Write("WARN", step, msg);
    public static void Error(string step, string msg)   => Write("ERROR", step, msg);
    public static void Debug(string step, string msg)   => Write("DEBUG", step, msg);

    private static void Write(string level, string step, string msg)
    {
        // 1. 级别过滤
        if (!ShouldLog(level)) return;

        // 2. 控制台输出
        if (ConsoleEnabled)
            Console.WriteLine($"[{level}] [{step}] {msg}");

        // 3. 数据库写入（异步，不阻塞主流程）
        if (DatabaseEnabled)
            Task.Run(() => WriteToDB(level, step, msg));

        // 4. 文件日志（可选）
        if (FileLogEnabled)
            WriteToFile(level, step, msg);
    }
}
```

### 2.5 改造步骤

#### 阶段 1：创建 LogHelper 类库

| 文件 | 变更 |
|------|------|
| `CommonOperateDll/LogHelper.cs` | 新增，实现上述 LogHelper 类 |
| 所有子程序的 `.csproj` | 确认已引用 CommonOperateDll（通常已引用） |

#### 阶段 2：替换各子程序的 Log 函数

| 文件 | 变更 |
|------|------|
| `load_machine/Program.cs` | 删除 `static void Log()`，替换为 `LogHelper.Info/Warn/Error` |
| `load_machine/transfer.cs` | 同上 |
| `change_machine/Program.cs` | 同上 |
| `prepare_material/Program.cs` | 同上 |
| `unload_machine/Program.cs` | 同上 |
| `backend/Program.cs` | 将 `Console.WriteLine` 和 `WriteStepLog` 替换为 `LogHelper` |

#### 阶段 3：清理散落的 Console.WriteLine

| 范围 | 变更 |
|------|------|
| 11 个文件 78 处 | 逐一替换为 `LogHelper.Info/Warn/Error`，保留重要调试输出改为 `LogHelper.Debug` |

#### 阶段 4：数据库清理

| 变更 | 说明 |
|------|------|
| `runlog` 表 | 不再建表，已有数据保留或迁移到 `process_log` |
| `processlog` → `process_status` | 改名，明确语义，与日志查询分离 |
| `process_log` 加索引 | 按 `log_level`、`step_name`、`created_at` 加索引 |
| 日志清理任务 | 按 `maxDays` 定期清理（在 `backend/Program.cs` 启动时加一个定时器） |

### 2.6 前端日志查询改进

**现有 `/api/logs`** 已支持分页查询，建议增强：

| 功能 | 说明 |
|------|------|
| 按级别过滤 | 加 `level` 参数（INFO/WARN/ERROR） |
| 按流程过滤 | 加 `step` 参数（load_machine / change_machine…） |
| 按时间范围 | 加 `startTime` / `endTime` 参数 |
| 按机床过滤 | 加 `machineId` 参数（依赖 `process_log` 新增字段） |
| 导出 CSV | 新增 `/api/logs/export` 接口 |

## 5. 风险与注意事项

- **向后兼容**：`process_log` 表结构变更（加 `machine_id`）需确保旧数据能正常显示，`machine_id` 允许为 NULL。
- **runlog 废弃**：如果现场有依赖 `runlog` 表的查询或报表，需先确认，迁移数据后再废弃。
- **processlog 改名**：`backend/Program.cs` 的 Dashboard 查询用到了 `processlog` 表（`/api/dashboard` 统计 `process_status`），改名后需同步更新查询语句。
- **异步写库**：`Task.Run(WriteToDB)` 需注意子程序退出时可能丢失最后几条日志，建议在子程序退出前加一个 `Flush()` 等待。
