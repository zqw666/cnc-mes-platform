## 2. 启动流程

### 2.1 后端启动

```
MachineMonitor.exe 启动
  │
  ├─ 1. 定位 config.json（与 exe 同级目录）
  │
  ├─ 2. 读取 database 配置
  │     ├─ 类型: MySQL / SQL Server
  │     ├─ 主机: localhost:3306
  │     ├─ 库名: qianduantest
  │     └─ 账号: root / 123456
  │
  ├─ 3. 连接数据库
  │     ├─ 尝试创建数据库（如不存在）
  │     └─ 检查/创建所有表（如不存在）
  │
  ├─ 4. 创建运行目录
  │     ├─ subs/      → 子进程存放目录
  │     └─ logs/      → 日志目录
  │
  ├─ 5. 启动 HTTP 服务
  │     ├─ 监听: http://127.0.0.1:8888/
  │     └─ 提供静态文件 + REST API
  │
  └─ 6. 输出就绪信息
        [MachineMonitor] 等待前端启动请求...
        (调用 /api/workflow/start 开始执行分包)
```

### 2.2 关键启动代码

```csharp
// Program.cs Main 函数核心逻辑
static void Main(string[] args) {
    // 1. 加载配置
    LoadConfig();

    // 2. 初始化数据库
    EnsureDatabase();     // 尝试创建数据库
    EnsureTables();       // 创建所有表
    EnsureDirectories();  // 创建 subs/ logs/

    // 3. 启动 HTTP
    var listener = new HttpListener();
    listener.Prefixes.Add($"http://127.0.0.1:{Port}/");
    listener.Start();

    // 4. 事件循环
    while (true) {
        var ctx = listener.GetContext();
        Task.Run(() => Handle(ctx));
    }
}
```

## 4. 工作流调度

### 4.1 读取步骤

```csharp
static List<ProcessFlowStep> GetEnabledSteps() {
    // 优先读取 work_flow 表（定制工作流，带优先级）
    SELECT id, processname, status, priority
    FROM work_flow WHERE status=1
    ORDER BY priority DESC, id ASC

    // 如果 work_flow 表无数据，则读 process_flow 表
    SELECT id, processname, status
    FROM process_flow WHERE status=1
    ORDER BY id
}
```

### 4.3 执行流程

```
RunWorkflow() 启动
  │
  ├─ 读取启用的步骤列表
  ├─ 遍历每个步骤，stepIndex = 1..N
  │
  ├─ 步骤 N:
  │   ├─ 更新 workflow_step 表状态为 "running"
  │   ├─ 启动子进程: subs/步骤名.exe
  │   │   └─ 传入参数: config.json 路径
  │   ├─ 重定向 stdout/stderr
  │   ├─ 等待子进程退出
  │   ├─ 检查暂停/取消信号
  │   ├─ 更新 workflow_step 表状态为 "completed"
  │   └─ 继续下一步
  │
  └─ 所有步骤完成 → 输出 "工作流全部步骤执行完毕"
```

## 5. 核心子进程详解（上机为例）

### 5.1 整体流程

```
load_machine.exe 启动
  │
  ├─ 1. 加载配置（config.json）
  │     ├─ 数据库连接信息
  │     ├─ PLC 信息（IP、端口、信号地址）
  │     └─ 机床列表（类型、IP、端口）
  │
  ├─ 2. 初始化机床连接
  │     ├─ 西门子 → OPC UA 连接
  │     └─ 罗德斯 → TCP 连接
  │
  ├─ 3. 连接 PLC（欧姆龙 FINS/UDP）
  │     └─ 失败则退出
  │
  ├─ 4. 查询待机机床
  │     └─ SELECT * FROM macmessage WHERE status!=0
  │        过滤条件: status="reset" AND workpiecename="" AND workpieceworkstate=0
  │
  ├─ 5. 判断工件来源
  │     ├─ 有随行台 → 读 following_rack 表 (posstatus=2, workstate=0)
  │     └─ 无随行台 → 读 robotmessage 表 (workpiecestatus=0)
  │
  ├─ 6. 置换夹爪（ChangeGripper）
  │     ├─ 固定爪模式 → 跳过（IsFixedGripper=true）
  │     └─ 非固定爪 → 读取 robotmessage 当前夹爪
  │         ├─ 类型匹配 → 跳过
  │         └─ 类型不匹配 → 去夹爪库换夹爪
  │
  ├─ 7. 执行上机
  │     └─ [详见下方 5.2]
  │
  └─ 8. 退出
```

### 5.3 ExecuteTask 通讯详解

这是整个系统中最核心的函数，负责通过 PLC 指挥机器人执行动作。

```csharp
static bool ExecuteTask(int tasknum) {
    // 1. 复位任务开始信号
    Plc.WriteWR("104.00", 0);

    // 2. 写入任务号到 DM 区
    Plc.WriteDM(100, tasknum);
    // DM100 = 任务号，对应机器人程序中的任务编号

    // 3. 发送任务开始信号
    Plc.WriteWR("104.00", 1);

    // 4. 等待任务完成信号（最多 300 秒）
    while (!Plc.ReadWR("100.02") && waitCount < 3000) {
        Thread.Sleep(100);
        waitCount++;
    }

    // 5. 超时检查
    if (!Plc.ReadWR("100.02")) return false;

    return true;
}
```

**任务号对应关系**：

| 任务号 | 含义 |
|--------|------|
| 随行台料位 ID | 机器人从随行台指定料位抓取工件 |
| 机床编号 (macmessage.id) | 机器人把工件放入指定机床 |

## 6. 设备通讯层

### 6.1 PLC 通讯（欧姆龙 FINS/UDP）

```
协议: FINS/UDP
PLC IP: 192.168.125.100
端口: 9600
```

| 操作 | 方法 | 说明 |
|------|------|------|
| 写 DM 区 | `Plc.WriteDM(100, 任务号)` | 设置机器人任务号 |
| 写 WR 位 | `Plc.WriteWR("104.00", 0/1)` | 任务开始/停止信号 |
| 读 WR 位 | `Plc.ReadWR("100.02")` | 读取任务完成信号 |
| 读 WR 字 | `Plc.ReadWR("100")` | 读取 WR 区字数据 |
| 写 WR 字 | `Plc.WriteWr("100", 值)` | 写入 WR 区字数据 |
| 读 DM 区 | `Plc.ReadDM(100)` | 读取 DM 区值 |

**PLC 信号地址表**（来自 config.json）：

```
plc.signals.robot:
  taskNumber: "100"     → DM 任务号地址
  taskStart:  "104.00"  → 任务开始信号
  taskDone:   "100.02"  → 任务完成信号
  error:      "100.01"  → 错误信号
  estop:      "103.01"  → 急停信号
  safePos:    ""        → 安全位置信号
```

#### 西门子（Siemens）— OPC UA

```
协议: OPC UA
```

## 7. 数据库表结构

### 7.1 核心表

#### macmessage — 机床主表

```sql
CREATE TABLE macmessage (
    id              INT,              -- 机床编号（也是任务号）
    machineip       VARCHAR(50),       -- 机床 IP
    machinetype     VARCHAR(50),       -- 机床类型
    status          INT,              -- 状态 (0=离线, 1=在线)
    workpiecename   VARCHAR(255),     -- 当前工件名称
    workpieceworkstate INT,           -- 工件加工状态 (0=待加工, 1=加工中)
    -- ...
);
```

#### macworkposstatus — 机床工位表

```sql
CREATE TABLE macworkposstatus (
    id              INT,
    machinename     INT,              -- 机床编号
    worknum         INT,              -- 工位号
    workpiecename   VARCHAR(255),     -- 工位上的工件
    posstatus       INT,              -- 工位状态 (0=空, 1=有料)
    workpiecestatus INT,              -- 工件加工状态 (0=待加工, 1=加工中)
    -- ...
);
```

#### following_rack — 随行台（上下料台）

```sql
CREATE TABLE following_rack (
    id              INT,              -- 料位号（也是任务号）
    workpiecename   VARCHAR(255),     -- 工件名称
    workpieceworkstate INT,           -- 工件状态
    posstatus       INT,              -- 料位状态 (0=空, 1=已占用, 2=待上机)
);
```

#### robotmessage — 机器人状态

```sql
CREATE TABLE robotmessage (
    id              INT,
    clampname       VARCHAR(255),     -- 当前夹爪名称
    clampstatus     INT,              -- 夹爪状态
    clampposstatus  INT,              -- 夹爪位置状态
    workpiecename   VARCHAR(255),     -- 夹爪上的工件
    workpiecestatus INT,              -- 工件状态 (0=待上机)
);
```

### 7.2 流程表

#### work_flow — 定制工作流

```sql
CREATE TABLE work_flow (
    id              INT,
    processname     VARCHAR(100),     -- 步骤名（如 loadmachine）
    status          INT,              -- 1=启用
    priority        INT,              -- 优先级（越大越先执行）
);
```

#### process_flow — 普通流程（work_flow 无数据时的备选）

```sql
CREATE TABLE process_flow (
    id              INT,
    processname     VARCHAR(100),
    status          INT,
);
```

#### workflow_step — 步骤执行状态

```sql
CREATE TABLE workflow_step (
    id              INT,
    step_name       VARCHAR(100),
    last_status     VARCHAR(50),      -- running / completed / error
    last_message    VARCHAR(500),
    last_time       DATETIME,
);
```
